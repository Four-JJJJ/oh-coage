# 日常交互与恢复出口

## 意图路由

| 用户意图 | 页面 / 操作 | 保存范围 |
|---|---|---|
| 换个模型 / 把模型改成 X | 确认厂家及主/备位置，打开完整模型配置表单 | 用户选择仅本次或保存 |
| 这张用 X 画 | 准确 ID / 唯一简称 → generate --model | 本次仅一个模型，不改配置 |
| 这次用 Gemini 画 | 已配置则 generate --family gemini | 本次 Gemini 主备链，不改默认厂家 |
| 以后用 Gemini | 完整表单，将默认厂家设为 Gemini | 保留所有其他厂家配置 |
| 管理/设置备选 | 同一完整表单，定位对应厂家 | 只改用户确认的主备 |
| 临时用另一个站点 | 现有配置单选 | 本次 generate --profile X |
| 以后用另一站点 | 现有配置单选，设为默认 | setup --activate-profile X |
| 添加站点 | 两步初始化 | 新 profile，不覆盖已有项 |
| 修改 URL / Key | 回填非敏感信息的连接编辑 | 验证及模型确认后原子替换 |
| 指定请求协议 / 使用厂家原生接口 | 连接编辑中的“生图请求协议”，确认对应厂家、地址和凭据 | 仅保存用户确认的连接；单次用 generate --api，不改配置 |
| 修改参考图发送方式 | setup 对应图生图适配项 | 指定 profile，不自动试付费格式 |

“把图片改成水彩”走编辑图像；“把模型改成 X”走切换。切换本身不生图。自然语言“切换”未说主备时先问“你想把它设为主模型，还是加入备选？”，厂家无法确定时一并确认；已经明确的槽位不重复问。备选只有一个槽位；已有备选时，替换前展示新旧模型供确认，不重复追加。

选择新的主模型时不自动把旧主塞进备选；新主若来自现有备选则移出，清空备选槽位。用户确认之前不写持久配置。生成时点名的厂家没有主模型，打开完整表单定位该组；不自动使用别家。

## 完整模型配置表单

执行 manage.js --snapshot / --render [--profile NAME]。初始化和日常使用相同分组与主备控件，日常回填已保存配置。当前站点目录为选择来源，不用跨站点合并列表。简称歧义列出真实 ID 让用户选。

收到 OH_COAGE_MODEL_SELECTION，将 `{profile,revision,action:"temporary"|"default",modelFamilies,activeFamily}` 经 stdin 交 manage.js --apply。default 保存所有用户确认的厂家设置及默认厂家；temporary 不写配置，只取所选厂家的主模型用于下一次 generate --profile / --model，不自动使用临时备选，页面必须如实说明。想临时使用已保存厂家的整组主备，直接用 --family。

- OH_COAGE_MODELS_REFRESH → manage.js --refresh，stdin {profile,revision}，全量分页刷新后重新 render。若有未保存编辑，提交刷新前明确会丢弃这些编辑，可取消回表单；刷新失败保留已保存的全部厂家设置。
- OH_COAGE_MODELS_EDIT → onboarding.js --edit-models，stdin {profile}，仍展示完整厂家配置；有草稿则用 complete 保存。
- OH_COAGE_PROFILES_SELECT → setup.js --list，展示已有配置单选，再确认仅本次/设为默认。回管理时沿用所选 profile。
- OH_COAGE_MANAGEMENT_CANCEL → 退出，不修改配置，返回原任务。

每家两个下拉框：主模型、备选模型（可选），不展示搜索、编号、清空或排序按钮。缺失模型显示待处理，可刷新、替换或移除，不默默删除。默认厂家被清空须另选已有主模型的组；全组清空不能保存，提供取消/连接其他站点。未知模型进入“其他模型”，兼容接口可用；需要原生协议时先明确对应厂家和连接，不猜协议。

默认向当前站点发送 OpenAI Images 格式；换模型、换默认厂家都不改变请求协议。只有用户明确要求才切换原生协议，不因模型名推断。原生连接仍受对应厂家约束，仅展示兼容厂家的两个选择器，其余厂家已保存配置保持休眠；提交前提供切回 OpenAI Images 格式/使用对应原生连接的出口，不自动切协议或地址。列表可见不证明出图能力。

过期 revision 拒绝覆盖，重新打开恢复当前设置，不自动重放旧提交。表单提交失败重新启用按钮，允许重试/取消。没有可用目录时提供刷新、准确手动 ID、编辑连接或其他站点入口，不困在空页面。

## 旧配置兼容

读取旧 model / fallback_models 时按厂家拆分，取每家第一项作为主模型、下一项作为唯一备选，多余旧备选不再执行；原主所属厂家默认启用。未知或失效 ID 保留，不把它们自动归入 OpenAI。读取不写盘，用户保存才落盘 model_families 和 active_model_family；兼容镜像字段只代表默认组，不能反向覆盖所有厂家。显式模型仍只用一个，自动主备不跨厂家。

## 配置生命周期

新增同名配置：拒绝覆盖，提供另起名称或编辑已有配置。重命名允许中文，密钥记录身份不随展示名称迁移。禁用/删除的配置不可激活，提供可用项/新增入口。

删除前列出精确配置名及影响，按宿主审批执行 setup.js --delete-profile NAME。删除 active 后选择其他启用项；没有可用项则回初始化。最后一项允许删除，保留图片、日志，不能逼用户卸载整个技能。仅当凭据不再被其他配置引用时清理。

卸载数据仅在用户明确要求后执行 setup.js --uninstall-skill；--keep-config-file、--keep-keychain、--purge-logs 对应明确保留/清理范围。不能因想重配站点就删全部配置。

配置文件损坏/路径失效时先报告路径，提供恢复原文件、选回正确配置路径或新位置初始化，不自动覆盖。Keychain 被锁/授权拒绝时给解锁重试入口，不反复弹窗或要求重复提供 Key。跨设备只有配置没有 Key 时在该设备重新连接。

## 生成结果的闭环

错误提示遵循 [errors.md](errors.md) 的固定文案。恢复入口依据实际拿到的任务编号和图片结果提供；只有诊断记录时不提示恢复查询或下载。服务未明确给出账单结果时，不判断扣款或退款。

| 当前状态 | 可做什么 | 不自动做什么 |
|---|---|---|
| 本地参数/目录错误，尚未提交 | 修参数/换目录，然后继续原请求 | 降低画质、丢参考图 |
| 模型明确不可用 | 仅尝试当前厂家的一个备选，仍失败则停止 | 改持久主备 |
| Key/余额/权限问题 | 编辑连接、核对额度、选择其他配置 | 把同一个 Key 当不同权限反复试 |
| 排队/长限流 | 告知等待时间，稍后继续/停止等待 | 绕过长 Retry-After 大量换模型 |
| 已知任务处理中 | 继续查询原任务/暂停等待 | 创建第二个任务 |
| POST 结果未知、无任务 ID | 核对服务商记录，待用户明确决定 | 声称未扣费、自动重跑 |
| 已有部分图片 | 展示已存图片，resume 补下载 | 为凑张数自动再生图 |
| URL 过期/原站点已删除 | 原任务重新取链接/恢复原连接/服务商任务页 | 以“恢复”名义重新计费 |
| 全部已允许尝试用完 | 报实际尝试、最后原因，提供管理模型/修连接/稍后再试 | 声称未尝试的站点也已失败 |

默认不跨站点；用户允许后才 --allow-profile-fallback。生成提交总上限默认 3；达到上限先停止，增加需用户决定。显式模型只使用该模型。参数错误/内容拒绝/未知结果不自动穿透备用链。

任务恢复为 generate.js --resume RECOVERY_JSON，只查询/下载，不生图。原配置路径与 URL 用于读取正确 Key，不能把 Key 自动转发到新地址。删除原配置后应先恢复原连接。临时连接的异步任务可在恢复时通过 IMAGES2_GEN_API_KEY 环境变量安全提供原密钥（兼容 --api-key，但避免出现在命令参数）；只请求恢复记录中的原地址，不保存密钥。已返回图片的下载恢复无需此 Key。

每次成功说明实际使用模型、张数、保存位置；少于请求张数明确标部分完成，不自动补生成。用户停止本地等待时说明远端可能还在执行；提供原任务恢复入口，不能承诺撤销服务端计费。
