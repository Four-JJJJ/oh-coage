# oh-coage

在 Agent 对话中连接自己的生图服务，选择模型，生成或编辑图片。支持 OpenAI、Gemini、Grok 等模型，服务地址和 API Key 由你提供。

当前版本：**0.11.0**。技能代码位于 [`skills/oh-coage`](skills/oh-coage)，运行需要 **Node.js 20+**；内置凭据存储使用 **macOS Keychain**。

## 能做什么

- **两步完成设置**：填写连接信息，再用下拉菜单选择模型。支持交互表单的宿主默认展示表单，其他环境通过文字完成相同流程。
- **按厂家管理主备**：每家一个主模型、一个可选备选，统一保存在同一个站点配置中。
- **文生图和参考图编辑**：接受本地图片、远程图片 URL 或 data URI，保存 URL / base64 返回的图片，并在对话中逐张展示。
- **单次指定或长期切换**：这次用哪个模型、以后默认用哪个厂家，分别处理。
- **保留结果，继续恢复**：查询或保存失败时恢复原任务，保留已保存图片，避免重复生成。

实际出图、参考图支持、参数和费用取决于你连接的服务及所选模型。模型出现在列表中，只代表服务返回了它，不代表已经验证出图能力或账户额度。

## 安装

先克隆仓库到一个固定位置：

```bash
git clone https://github.com/Four-JJJJ/oh-coage.git
cd oh-coage
```

推荐将 **`skills/oh-coage` 子目录**软链到宿主的技能目录。下面的命令在仓库根目录执行：

Codex（个人技能目录）：

```bash
mkdir -p ~/.agents/skills
ln -s "$PWD/skills/oh-coage" ~/.agents/skills/oh-coage
```

Claude Code：

```bash
mkdir -p ~/.claude/skills
ln -s "$PWD/skills/oh-coage" ~/.claude/skills/oh-coage
```

目标位置已有同名技能时，先检查现有安装，不直接覆盖。也可以把 `skills/oh-coage` 整个目录复制到宿主支持的技能目录；复制安装后需另行更新该副本。

仓库根目录的 [`SKILL.md`](SKILL.md) 是兼容整仓安装的入口指针。实际执行说明与脚本均在 `skills/oh-coage` 中；后文的 `$SKILL_DIR` 指这个子目录的绝对路径。

安装只获取代码，不包含服务配置、API Key 或生成图片。每台 Mac 分别完成初始化；其他系统尚未提供替代 Keychain 的完整初始化方案。

## 第一次使用

在对话中说：

> 使用 oh-coage 生成一张海边灯塔的图片。

没有配置时，Agent 会先启动初始化。设置完成后，在符合宿主费用授权规则的前提下继续原来的创作请求。

### 第一步：连接你的生图服务

填写三个必需字段：

| 字段 | 填什么 |
|---|---|
| 配置名称 | 方便识别这个站点的名称，例如“日常创作” |
| 服务地址 | 服务商提供的 API 基础地址，例如 `https://example.com/v1` |
| API Key | 该站点的访问密钥 |

保存目录和生图请求协议放在“更多设置”中。未指定目录时，优先使用当前 Git 仓库或识别到的项目根目录；没有项目标记时使用当前工作目录，在用户主目录、桌面、文稿或下载目录中启动则回落到桌面。生成结果按任务建立时间子目录。

脚本验证模型列表接口，并全量读取支持的分页列表，通过后进入第二步。验证失败会提示原因，可以修改、重试或取消；不会覆盖已有配置，也不会通过实际生图验证连接。

服务明确不支持模型列表、返回空列表或首屏格式不兼容时，可以使用服务商提供的准确模型 ID 手动配置。这种方式会标记“连接鉴权与出图能力未验证”，不能用于绕过鉴权失败或网络错误。

### 第二步：配置你的模型

列表按 OpenAI、Gemini、Grok 和其他模型分组。每家只有两个下拉菜单：

| 选择器 | 规则 |
|---|---|
| 主模型 | 该厂家的默认生成模型；任意一家选好主模型即可完成设置 |
| 备选模型（可选） | 最多一个，必须与主模型属于同一厂家；可以留空 |

只展示当前列表中有模型且与请求协议兼容的厂家。无法识别的模型保留在“其他模型”，不直接丢弃。配置多家时，再选择一个默认厂家；只有一家时自动使用它。

保存后运行本地检查，展示配置名称、默认厂家、主备模型和保存位置。此检查不验证实际出图或计费。返回或取消都有对应入口；取消本次设置不会删除已有配置。

可视化表单需要宿主同时支持 inline HTML 和 `window.openai.sendFollowUpMessage`。缺少提交能力时，Agent 使用固定文字流程，收集相同信息。

## 日常使用

| 你可以这样说 | 会发生什么 |
|---|---|
| “生成一张雨中的街景” | 使用当前站点、默认厂家的主模型 |
| “这张用 banana 画” | 在当前站点解析准确 ID 或唯一简称，仅本次使用，不修改配置；有多个候选时请你选择 |
| “这次用 Gemini 画” | 使用已保存的 Gemini 主备设置，不改变默认厂家；未配置则打开模型设置 |
| “切换模型” / “把模型改成 X” | 未说明主备位置时先确认，再打开回填当前设置的完整模型表单 |
| “把 Grok 的主模型改成 X” | 定位 Grok 主模型，保留未涉及的其他设置 |
| “以后默认用 Gemini” | 打开模型表单，确认将默认厂家设为 Gemini |
| “管理备选模型” | 在同一表单中调整主模型和一个可选备选 |
| “刷新模型” | 全量刷新当前站点列表，失败保留旧列表和配置 |
| “切换站点” | 选择已有配置，并区分仅本次使用或设为默认 |
| “添加站点” / “更新 Key” | 进入连接设置流程，验证后保存 |
| “继续下载刚才的图片” | 使用原任务记录恢复保存，不重新生成 |

模型管理表单可选择“保存为默认”或“仅本次”。**仅本次使用表单中所选厂家的主模型，不自动使用临时备选，也不写入配置**；通过“这次用 Gemini”使用已保存厂家设置时，才保留该组主备。

换主模型不会自动把旧主模型放入备选；将现有备选设为主模型时，备选槽位清空。主模型改为“暂不设置”也会清空该组备选。其他厂家配置保持不变。

### 主备模型：首选 + 备用写在同一个 profile 里

一个 profile 表示一组站点连接。同一 profile 内可以同时保存多个厂家的设置：

```text
日常创作（一个服务地址 + 一组密钥）
  OpenAI    主模型 + 可选的一个备选
  Gemini    主模型 + 可选的一个备选
  Grok      主模型 + 可选的一个备选
  其他模型  主模型 + 可选的一个备选
  默认厂家  从已配置主模型的厂家中选择
```

主模型被服务**明确拒绝为不可用**，例如模型不存在或模型权限拒绝时，最多尝试一个同厂家备选。超时、结果未知、余额不足、普通权限错误、内容拒绝或参数错误不会触发模型切换。显式指定单个模型时只尝试该模型。实际使用了备选会报告完整模型 ID，不改变持久主模型。

跨站点备选默认关闭，只有明确允许时才开启。所有生成提交合计默认最多 3 次，包含安全重试和备选尝试，不自动增加上限。

配置保存为 `profile.model_families` 和 `profile.active_model_family`；`profile.model` / `profile.fallback_models` 镜像默认厂家，兼容旧客户端。旧 `--primary-model` / `--fallback-model` 仍可维护对应厂家设置，日常使用优先走表单。结构化生成结果中的 `used_fallback_model` 表示本次是否实际使用备选。

旧配置读取时按厂家拆分，每家第一项作为主模型、下一项作为唯一备选，多余旧备选不执行；读取不改写原文件，用户保存时才更新结构。9 个内置模型用于旧配置与简称支持，不能代替当前站点的真实模型列表。

## 请求协议

**默认发送 OpenAI Images 格式，模型厂家和请求协议分别设置。** 选择 Gemini 或 Grok 模型，不会自动改为厂家原生接口，也不会自动改地址。

| 请求方式 | 使用方式 |
|---|---|
| OpenAI Images 格式（默认） | 发到你配置的站点；可使用该站点支持的不同厂家模型 |
| 厂家原生协议 | 在“更多设置”中明确指定，或在对话中要求；确认对应厂家、地址和凭据后使用 |

原生连接只能使用对应厂家的兼容模型。协议不匹配时在提交前提示调整连接或选择兼容模型，不向错误接口盲发。`--family` 选择本次模型厂家，`--api` 选择请求格式，两者作用不同。

## 失败后如何继续

提示先说明原因与当前状态，再给出可执行的下一步。原始错误放在技术详情中，不作为主要提示。

| 遇到的情况 | 处理方式 |
|---|---|
| 本地参数、参考图或保存目录不合适 | 提交前停止，调整后继续，不静默降低画质或丢参考图 |
| 密钥无效、余额或额度不足 | 提示检查连接或账户；余额错误包括 `429 insufficient_quota`，不按限流重试 |
| 真正的限流 | 尊重 `Retry-After`，有限重试；要求等待超过 60 秒时停止，提示稍后再试 |
| 超时、断线、408/5xx、响应格式异常 | 暂停全部生成提交，说明结果尚未确认；有任务编号则恢复查询，否则先核对服务记录 |
| 已收到图片，但下载或保存失败 | 恢复原图片保存，可更换目录，无需重新生成 |
| 部分图片已保存 | 保留并展示已有图片，说明实际张数，不自动补生成 |
| 服务明确返回任务失败、取消或完成却无图 | 如实提示服务结果，核对原任务，不循环提交 |

有记录文件不代表一定能恢复：必须有任务编号或图片结果才提供恢复入口。只停止本地查询不能保证服务端任务已取消；结果未知时不推断扣款或退款。详细文案和分支见 [错误提示与恢复](skills/oh-coage/references/errors.md)。

## 脚本入口

日常使用直接在对话中表达意图即可。需要调试或集成时，先将 `SKILL_DIR` 设置为本机 `skills/oh-coage` 的绝对路径；以下生成示例会请求你配置的服务，可能产生费用。

```bash
# 查看配置与本地状态
node "$SKILL_DIR/scripts/setup.js" --list
node "$SKILL_DIR/scripts/setup.js" --health-check

# 使用默认模型，返回结构化结果
node "$SKILL_DIR/scripts/generate.js" --prompt "海边的灯塔" --json

# 仅本次使用已配置的 Gemini 主备，不改变默认厂家
node "$SKILL_DIR/scripts/generate.js" --family gemini --prompt "山间木屋" --json

# 仅本次使用当前站点的准确模型 ID，不自动使用备选
node "$SKILL_DIR/scripts/generate.js" --model "站点实际模型ID" --prompt "雨中的街景" --json

# 使用本地参考图；站点和模型需支持编辑
node "$SKILL_DIR/scripts/generate.js" --prompt "把这张图改成水彩" --image-url "/absolute/path/photo.png" --json

# 恢复原任务查询或保存；不提交生成 POST
node "$SKILL_DIR/scripts/generate.js" --resume "/absolute/path/recovery-xxx.json" --out-dir "/absolute/path/images" --json
```

`--json` 的成功结果包含实际模型、图片路径、展示引用、请求与收到张数；返回不足时标记 `partial`。不加该参数时，通常逐行输出保存路径。

图生图的字段、JSON / multipart 传输和端点可按站点配置。4K 只支持 `16:9`、`9:16`、`2:1`、`1:2`、`21:9`、`9:21`；其他组合会在提交前报错，需要选择支持的比例或明确改用 2K。完整参数以 [技能执行说明](skills/oh-coage/SKILL.md) 为准。

## 数据与更新

| 位置 | 内容 |
|---|---|
| macOS Keychain，服务名 `oh-coage` | 正式连接密钥及未完成初始化的临时凭据 |
| 保存目录下的 `oh-coage-config.json` | 站点、模型设置及凭据引用，不含 API Key |
| `~/.oh-coage/state.json` | 本机当前配置文件位置 |
| `~/.oh-coage/onboarding/` | 初始化草稿，含非敏感设置；有效期 24 小时 |
| `~/.oh-coage/runs.jsonl` | 运行日志，包含提示词等任务信息 |
| 图片任务目录 | 图片、元数据和恢复记录；恢复记录可能包含图片 URL 或 base64 结果 |

表单提交通过当前对话传给本机脚本，不能承诺密钥从未进入会话。浏览器表单不直接请求服务商；密钥不写入浏览器存储。跨设备复制配置不等于同步 Keychain，每台设备需要自己的可用凭据。

删除配置与卸载按明确范围操作，图片和日志不会因取消设置而删除。配置损坏、模型列表刷新失败或旧表单过期时保留已有数据，提供修复、重开或取消入口。

软链安装可在本地无冲突时通过 `git pull --ff-only` 更新；有本地修改时先保留并处理差异。复制安装需检查源目录与安装副本差异，再更新技能文件。更新代码不需要删除个人配置或重新填写密钥。
